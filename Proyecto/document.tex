\begin{abstract}
	En este trabajo se utilizó el dataset público de Olist\cite{olist_dataset}, una plataforma de comercio electrónico en Brasil, para predecir cuántos días tarda en llegar cada pedido. Se unificaron los datos de órdenes, clientes, vendedores y ubicaciones geográficas, y se calculó la distancia entre cada cliente y su vendedor. Para evitar usar información del futuro durante el entrenamiento, se dividieron los datos de forma cronológica. Se probaron varios modelos de aprendizaje automático: Random Forest, XGBoost, LightGBM\cite{ke2017lightgbm} y CatBoost\cite{prokhorenkova2018catboost}. El mejor resultado lo obtuvo CatBoost con su configuración por defecto (MAE de 4.2 días). Un hallazgo interesante fue que la distancia geográfica resultó ser el factor más importante, y que los estados del norte de Brasil tienen entregas hasta 3 veces más lentas que los del sudeste. Curiosamente, intentar ajustar los hiperparámetros empeoró los resultados en todos los casos.
\end{abstract}

\section{Introducción}

Cuando compramos algo en línea, una de las primeras preguntas que nos hacemos es: ¿cuándo va a llegar? Para las tiendas de comercio electrónico, poder responder esta pregunta con precisión es fundamental para mantener contentos a sus clientes.

En este trabajo nos propusimos predecir el tiempo de entrega de pedidos usando datos reales de Olist\cite{olist_dataset}, una de las plataformas de \textit{e-commerce} más grandes de Brasil. El dataset incluye información sobre casi 100 mil órdenes: quién compró, quién vendió, desde dónde se envió y hacia dónde. Nuestro objetivo fue construir un modelo que, dado un pedido nuevo, pueda estimar cuántos días tardará en llegar.

\section{Metodología}

\subsection{Datos y construcción del conjunto}

Los datos provienen de una base SQLite con la versión pública del dataset de Kaggle. Unimos varias tablas (órdenes, productos, clientes, vendedores y ubicaciones) para crear un solo conjunto de datos con toda la información relevante. Solo conservamos las órdenes que ya fueron entregadas y que tenían todos sus datos completos, lo que nos dejó con 95{,}978 pedidos y 22 variables.

Las variables principales que usamos son:
\begin{itemize}
	\item Información del pedido: precio total, costo de envío, peso, volumen y cantidad de productos.
	\item Ubicación: coordenadas del cliente y del vendedor (promediadas por código postal). Si un pedido tenía varios vendedores, promediamos sus ubicaciones.
	\item Distancia: calculamos los kilómetros entre cliente y vendedor usando la fórmula geodésica.
	\item Tiempo de compra: mes, día de la semana y hora en que se hizo el pedido.
	\item Variable a predecir: días que tardó la entrega (fecha de entrega menos fecha de compra).
\end{itemize}

\subsection{Ingeniería de características}

Después de explorar los datos, creamos nueve variables adicionales que podrían ayudar a los modelos a hacer mejores predicciones:
\begin{enumerate}
	\item \textbf{Categoría de distancia}: agrupamos las distancias en cuatro rangos: local (menos de 100 km, 17{,}852 pedidos), regional (100--500 km, 37{,}123 pedidos), larga distancia (500--1000 km, 25{,}678 pedidos) y muy larga (más de 1000 km, 15{,}302 pedidos).
	\item \textbf{Mismo estado}: indica si el cliente y el vendedor están en el mismo estado (esto ocurre en el 36\% de los pedidos).
	\item \textbf{Densidad}: peso dividido entre volumen. Creamos esta variable porque peso y volumen están muy correlacionados entre sí ($r=0.83$).
	\item \textbf{Precio por producto}: el precio total dividido entre la cantidad de productos.
	\item \textbf{Costo de envío por kilómetro}: el flete dividido entre la distancia (más uno, para evitar dividir entre cero).
	\item \textbf{Cliente en zona remota}: marca si el cliente está en estados del norte de Brasil (RR, AP, AM, AC, RO, PA), que son solo el 1.6\% de los clientes.
	\item \textbf{Vendedor en zona remota}: lo mismo pero para vendedores (apenas el 0.03\%).
	\item \textbf{Compra en fin de semana}: indica si el pedido se hizo en sábado o domingo (23\% de los casos).
	\item \textbf{Compra en horario laboral}: indica si se compró entre 9 y 18 horas (62\% de los casos).
\end{enumerate}
Las variables de zona remota buscan capturar la gran diferencia que existe en tiempos de entrega entre el norte y el sudeste de Brasil.

\subsection{Partición y preprocesamiento}

Un aspecto importante en este tipo de problemas es no usar información del futuro para predecir el pasado. Por eso, ordenamos todos los pedidos por fecha y dividimos los datos de forma cronológica: el 20\% más reciente quedó como conjunto de prueba, y del 80\% restante, el último 15\% se usó para validación. Así nos aseguramos de que el modelo siempre se evalúe con datos ``del futuro''.

Para el preprocesamiento, las variables categóricas (como el estado del cliente) se convirtieron a formato \textit{one-hot}, mientras que las numéricas se dejaron sin modificar, ya que los modelos de árboles no necesitan que estén escaladas.

\subsection{Modelos y métricas}

Para medir qué tan bien predicen los modelos, usamos el MAE (error absoluto medio) como métrica principal y el RMSE como complemento. El MAE nos dice, en promedio, por cuántos días nos equivocamos.

Probamos cuatro tipos de modelos, todos basados en árboles de decisión:
\begin{itemize}
	\item Random Forest con 200 árboles, como punto de referencia inicial.
	\item XGBoost, tanto con configuración por defecto como ajustado.
	\item LightGBM, que es más rápido para entrenar\cite{ke2017lightgbm}.
	\item CatBoost, diseñado especialmente para manejar variables categóricas\cite{prokhorenkova2018catboost}.
\end{itemize}

Para intentar mejorar los modelos, usamos búsqueda aleatoria de hiperparámetros con 50 combinaciones por modelo, probando diferentes valores de profundidad, tasa de aprendizaje, número de árboles y regularización.

\section{Resultados}

\subsection{Exploración de los datos}

Antes de entrenar los modelos, exploramos los datos para entender mejor el problema. La mayoría de los pedidos llegan entre 7 y 15 días, con una mediana de 10.2 días y un promedio de 12.5 días. Sin embargo, hay una cola larga de pedidos que tardan mucho más: encontramos 4{,}891 casos (el 5.1\%) que superan los 29 días, y el más extremo tardó casi 210 días. La Figura~\ref{fig:distribucion} muestra esta distribución.

\begin{figure}[H]

	\label{fig:distribucion}

También encontramos patrones interesantes en el tiempo. Agosto es el mes con más pedidos, mientras que septiembre cae bastante. En cuanto a horarios, la mayor actividad ocurre entre las 3 y las 8 de la tarde. Pero lo más llamativo es la diferencia en tiempos de entrega según el mes: febrero es el más lento (16.2 días en promedio) y agosto el más rápido (9.1 días), una diferencia de 7 días. La Figura~\ref{fig:temporales} resume estos patrones.

Al analizar las correlaciones (Figura~\ref{fig:correlacion}), la distancia resultó ser la variable numérica más relacionada con el tiempo de entrega ($r=0.39$). El costo de envío tiene una relación más débil con el tiempo ($r=0.17$), y en cambio está más asociado con el peso del paquete ($r=0.64$) y la distancia ($r=0.32$). \subsection{Comparación de modelos}

La Tabla~\ref{tab:modelos} muestra cómo le fue a cada modelo en el conjunto de prueba. Usamos Random Forest como punto de partida, y a partir de ahí comparamos los demás.

Lo primero que llama la atención es que ajustar los hiperparámetros no ayudó: en todos los casos, las versiones ``ajustadas'' fueron iguales o peores que las de configuración por defecto. El peor caso fue Random Forest, donde el ajuste empeoró el MAE en un 13\%.

El mejor modelo resultó ser CatBoost con su configuración por defecto, logrando un MAE de 4.25 días. LightGBM quedó muy cerca con 4.29 días. Ambos superaron a Random Forest por un 4--5\%.

Algo a notar es que todos los modelos tienen un sesgo negativo de alrededor de -2.4 días, lo que significa que tienden a predecir tiempos un poco más largos de lo real. Esto no es necesariamente malo: es mejor decirle al cliente que su pedido llegará en 12 días y que llegue en 10, que prometerle 10 y que llegue en 12.

\subsection{¿Qué variables importan más?}

Del análisis exploratorio y los resultados de los modelos, podemos ordenar las variables por su importancia:
\begin{enumerate}
	\item \textbf{Distancia}: es el factor más importante. Cada 1000 km adicionales añaden unos 6 días al tiempo de entrega.
	\item \textbf{Ubicación geográfica}: los estados del norte tardan 3 veces más que los del sudeste. Las variables que creamos para marcar zonas remotas capturan este efecto.
	\item \textbf{Mismo estado}: cuando cliente y vendedor están en el mismo estado (36\% de los casos), las entregas son notablemente más rápidas.
	\item \textbf{Características del paquete}: el peso, volumen y densidad tienen poca relación con el tiempo. Lo que importa es la distancia, no el tamaño.
	\item \textbf{Momento de compra}: comprar en fin de semana o fuera de horario laboral casi no afecta el tiempo de entrega (menos de medio día de diferencia).
\end{enumerate}
En resumen, la geografía lo explica casi todo. Las características del producto y cuándo se compra tienen un efecto menor.

\section{Limitaciones}

Nuestro trabajo tiene varias limitaciones que vale la pena mencionar:
\begin{itemize}
	\item Asumimos que las condiciones logísticas se mantienen estables, pero en la realidad cambian todo el tiempo (disponibilidad de productos, capacidad de transporte, clima, etc.).
	\item No incluimos variables externas que podrían ser útiles, como feriados, condiciones climáticas o eventos especiales que afecten el transporte.
	\item El modelo tiende a sobreestimar el tiempo de entrega por unos 2.4 días. Aunque esto es preferible a quedarse corto, podría mejorarse con técnicas de calibración.
\end{itemize}

\section{Trabajo relacionado}

Los modelos basados en árboles son muy populares para este tipo de problemas. Random Forest, propuesto por Breiman\cite{breiman2001random}, combina muchos árboles de decisión para hacer predicciones robustas. XGBoost\cite{chen2016xgboost} mejoró esta idea usando \textit{gradient boosting} y se volvió muy popular en competencias de ciencia de datos. LightGBM\cite{ke2017lightgbm} hizo el entrenamiento más rápido usando histogramas, mientras que CatBoost\cite{prokhorenkova2018catboost} se diseñó específicamente para manejar mejor las variables categóricas. Todos estos modelos se usan comúnmente para predecir tiempos de entrega en comercio electrónico porque ofrecen un buen balance entre precisión y velocidad.

\section{Conclusiones y trabajo futuro}

El hallazgo principal de este trabajo es que la distancia geográfica es, por mucho, el factor más importante para predecir cuánto tardará un pedido en llegar. La diferencia entre estados del norte y del sudeste de Brasil es enorme: hasta 3 veces más lento.

Entre los modelos que probamos, CatBoost con su configuración por defecto fue el mejor, logrando predecir el tiempo de entrega con un error promedio de 4.2 días. Un resultado sorprendente fue que intentar ajustar los hiperparámetros no solo no ayudó, sino que empeoró los resultados.

Para mejorar este trabajo en el futuro, proponemos tres líneas:
\begin{itemize}
	\item Corregir el sesgo del modelo para que no sobreestime tanto el tiempo.
	\item Incluir información adicional como feriados, clima o capacidad logística.
	\item Entrenar modelos específicos para diferentes regiones, ya que el norte y el sudeste se comportan de forma muy diferente.
\end{itemize}
